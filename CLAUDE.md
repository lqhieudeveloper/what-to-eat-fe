# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev          # start dev server
pnpm build        # tsc + vite build
pnpm check-type   # TypeScript type-check (no emit, no fix)
pnpm lint         # eslint check
pnpm lint:fix     # eslint auto-fix
pnpm format       # prettier write
pnpm test         # vitest watch mode
pnpm test:run     # vitest single run (CI)
pnpm preview      # preview production build
```

Pre-commit hook runs in order — all must pass before commit is allowed:

1. `lint-staged` — ESLint + Prettier on staged files
2. `check-type` — TypeScript full project
3. `test:run` — all Vitest test cases

## Tech Stack

- **React 19** + **TypeScript 6** + **Vite 8**
- **Tailwind CSS v4** — CSS-first config, no `tailwind.config.js`. All design tokens in `src/index.css` under `@theme inline`.
- **shadcn/ui** (new-york style, neutral base) — installed components live in `src/ui/`. Add new ones via `pnpm dlx shadcn@latest add <component>` then move to `src/ui/<name>/<name>.tsx`.
- **TanStack Query v5** — all server state. No `useEffect` data fetching in components.
- **Zustand v5** — client/UI state in `src/stores/`.
- **Zod v4** + **react-hook-form** + **@hookform/resolvers** — form state and validation. Always pair together.
- **axios** — HTTP client, configured in `src/axios/`.
- **Vitest** + **React Testing Library** — unit tests, scoped to `src/ui/` only.

## Directory Layout (`src/`)

```
axios/           # Shared axios instance with error handling + Bearer token interceptor
components/      # Page-specific shared components — one folder per page (PascalCase)
                 # e.g. components/Homepage/HeroSection.tsx
                 # e.g. components/Homepage/HeroSection.tsx
constants/       # App-wide constants — files in kebab-case, values in UPPER_CASE
                 # e.g. constants/api-routes.ts → export const API_ROUTES = { ... }
hooks/           # Reusable React hooks — one folder per page (PascalCase), files in kebab-case
                 # e.g. hooks/Homepage/use-food-filter.ts
icons/           # SVG icons only — PascalCase component files, export default returns <svg>
                 # e.g. icons/FoodIcon.tsx
queries/
  mutations/     # TanStack Query useMutation hooks (POST, PUT, PATCH, DELETE)
                 # e.g. queries/mutations/Homepage/useCreateFood.ts
  query/         # TanStack Query useQuery hooks (GET)
                 # e.g. queries/query/Homepage/useFoodList.ts
schema/          # Zod form schemas — one file per page in camelCase
                 # e.g. schema/homepageSchema.ts
services/        # Static-method classes for backend calls — one file per page (PascalCase)
                 # e.g. services/HomepageService.ts
stores/          # Zustand stores — one file per domain, export hook directly
                 # e.g. stores/useFilterStore.ts
styles/          # Global CSS files for the project
types/           # TypeScript types — one folder per page (camelCase)
  foodList/
    entities.ts    # Types used directly by React components (PascalCase names, camelCase fields)
    requests.ts    # Types for API call payloads from components → hooks → services (camelCase fields)
    responses.ts   # Raw backend response shapes, used only in services (snake_case fields allowed)
pages/           # TanStack Router file-based routes — one file per URL segment
                 # __root.tsx → root layout (TooltipProvider, Toaster, Outlet)
                 # index.tsx → homepage (path: /)
                 # kebab-case file name = URL path segment (food-list.tsx → /food-list)
routeTree.gen.ts # Auto-generated by TanStack Router Vite plugin — DO NOT edit manually
ui/              # shadcn component primitives — one folder per component
                 # e.g. ui/button/button.tsx + ui/button/index.ts (re-export)
utils/           # Shared helper functions — files in kebab-case
                 # e.g. utils/utils.ts (cn helper), utils/format-date.ts
```

### Data Fetching Flow

**Always** follow this direction — never skip a layer:

```
components/Homepage/FoodList.tsx             ← calls hook only, zero axios/service imports
    ↓
queries/query/Homepage/useFoodList.ts        ← useQuery wrapping the service
queries/mutations/Homepage/useCreateFood.ts  ← useMutation wrapping the service
    ↓
services/HomepageService.ts                  ← static axios calls + response/request mapping
```

React components must **never** import or call a service directly.

### Service Pattern

Services use **static methods only**. No class instantiation.

```ts
// services/HomepageService.ts
export class HomepageService {
  static async getFoodList(params: GetFoodListRequest) {
    const res = await axiosInstance.get<FoodListResponse>('/foods', { params })
    return HomepageService.mapFoodList(res.data)
  }

  private static mapFoodList(raw: FoodListResponse) {
    return {
      listData: raw.list_data,
      totalCount: raw.total_count,
    }
  }
}
```

### Data Mapping in Services

Services are the **single mapping boundary**. Components and TanStack hooks always work with camelCase.

**Response** (backend → app): map snake_case fields to camelCase inside the service.

**Request** (app → backend): map camelCase payload fields to whatever the API expects.

```ts
// Request mapping example
static async createFood(payload: CreateFoodRequest) {
  return axiosInstance.post('/foods', {
    food_name: payload.foodName,
    category_id: payload.categoryId,
  })
}
```

### Error Handling

- Services let axios errors propagate — do not swallow them.
- TanStack Query hooks expose `isError` / `error` — use these in components for conditional UI.
- For mutation errors, show a Sonner toast inside `onError` of `useMutation`.

```ts
useMutation({
  mutationFn: HomepageService.createFood,
  onError: (error) => toast.error(error.message),
})
```

### Zustand Stores

One file per domain in `src/stores/`. Export the hook directly (no separate selector files).

```ts
// stores/useFilterStore.ts
import { create } from 'zustand'

type FilterStore = {
  selectedDate: string
  setSelectedDate: (date: string) => void
}

export const useFilterStore = create<FilterStore>((set) => ({
  selectedDate: '',
  setSelectedDate: (date) => set({ selectedDate: date }),
}))
```

### Types Structure

Per page, three files with distinct responsibilities:

- `entities.ts` — types the React component UI directly uses (PascalCase names, camelCase fields)
- `requests.ts` — types for API call payloads passed from components → TanStack hooks → services (camelCase fields)
- `responses.ts` — raw backend response shapes consumed only inside services (snake_case fields allowed)

### React Component Variables

Inside React components, always use **camelCase** for all variables and type fields.

```ts
// ✓
const foodList = useFoodList()
const { listData, totalCount } = foodList

// ✗
const food_list = ...
const FoodList = ...   // PascalCase only for component/type names, not variables
```

### Environment Variables

Use `VITE_` prefix. Access via `import.meta.env.VITE_*`. Define in `.env.local` (not committed).

```
VITE_API_BASE_URL=http://localhost:8080
```

The axios instance in `src/axios/` reads `import.meta.env.VITE_API_BASE_URL` as `baseURL`.

### Providers Setup

Provider order in `src/main.tsx` (outermost → innermost):

1. `QueryClientProvider` — wraps everything (TanStack Query)
2. `RouterProvider` — renders the router (TanStack Router)
3. `TooltipProvider` + `Toaster` (Sonner) — inside `__root.tsx` layout, not main.tsx

`ReactQueryDevtools` sits alongside `RouterProvider` in main.tsx (dev only, toggled by its own button).

### TanStack Router

File-based routing via `@tanstack/router-plugin/vite`. Route tree at `src/routeTree.gen.ts` is auto-generated on `pnpm dev` / `pnpm build` — never edit it manually.

- `src/pages/__root.tsx` — root layout, always rendered
- `src/pages/index.tsx` — homepage route (`/`)
- `src/pages/food-list.tsx` — maps to `/food-list`
- Nested: `src/pages/food/index.tsx` + `src/pages/food/$id.tsx` → `/food` and `/food/:id`

When adding a new page, also create the route file in `src/pages/`. Use `/add-page` command.

### Styling

- Use semantic token classes: `bg-background`, `text-foreground`, `border-border`.
- Brand colors: `bg-brand-primary`, `text-brand-secondary`, `bg-success`, etc.
- Dark mode via `.dark` class (`@custom-variant dark (&:is(.dark *))`).
- Use `cn()` from `@/utils/utils` to merge conditional classes.

### UI Components

All UI primitives come from `src/ui/` (shadcn). Add new ones via `/add-shadcn`.

### Forms

Always use **react-hook-form** + **Zod** via `@hookform/resolvers/zod`. Schema goes in `src/schema/`. Validate at schema level, not inside components.

```ts
import { useForm } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import { z } from 'zod'
import { foodSchema } from '@/schema/foodSchema'

type FoodFormValues = z.infer<typeof foodSchema>

const form = useForm<FoodFormValues>({ resolver: zodResolver(foodSchema) })
```

### Unit Tests

Tests are scoped **only to `src/ui/`** (shadcn components). No test files should be created outside `src/ui/`. Pattern: `src/ui/<name>/<name>.test.tsx`.

## shadcn CLI Note

`pnpm dlx shadcn@latest init` has a Windows bug (creates a literal `@/` directory). The `add` command works fine but installs to the wrong path — move files manually to `src/ui/<name>/<name>.tsx` and create `src/ui/<name>/index.ts` with `export * from './<name>'`. Use the `/add-shadcn` command to automate this.
